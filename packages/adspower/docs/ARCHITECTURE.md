## 1. What it does

It controls the AdsPower desktop app through its **Local API**, an HTTP
server AdsPower runs on `http://127.0.0.1:50325` while it's open:

- open the app; check it's running
- list/filter **groups**, **profile tags**, **profiles**, **proxies**
- find one profile (serial number, ID, or text) and **open/close** its browser
- **create** a profile already filed under a group and tag
- **change the proxy** of an existing profile, only from proxies with the right tag

All of it is available two ways: the `adspower` command, and the
`AdsPower` class in Python. The command is a thin layer over the class.

## 2. Module map

Each module has **one job**. A module's name says what that job is.

```text
src/mrfactory/adspower/
├── __init__.py    public API: the names users may import
├── __main__.py    `python -m mrfactory.adspower` → cli.main()
│
├── client.py      AdsPower: what to do, and the rules (facade)
├── api.py         LocalApi: how to talk HTTP to AdsPower (transport)
├── models.py      Group, Tag, Profile, Proxy, OpenedBrowser (data)
├── matching.py    what counts as a name/text match (pure rules)
├── errors.py      AdsPowerError and its family
├── launcher.py    find AdsPower.exe and start it
│
└── cli/           the `adspower` command
    ├── app.py       entry point: parser, run one command, safe exit
    ├── commands.py  one cmd_* function per subcommand
    ├── prompts.py   asking the user: pick, confirm, is anyone there?
    └── output.py    tables and JSON
```

**Who imports whom.** Arrows point from the importer to what it uses.
There are no cycles, and nothing below `client.py` knows the CLI exists:

```text
            cli/app ──▶ cli/commands ──▶ cli/prompts
               │              │      └─▶ cli/output
               ▼              ▼
             client.py ──────────────────┐
           ┌────┼──────────┬──────────┐  │
           ▼    ▼          ▼          ▼  ▼
        api.py launcher.py models.py ─▶ matching.py
           │                  ▲
           ▼                  │
        errors.py ◀───────────┘ (everyone may raise these)
```

This is a **layered architecture**, packaged **by layer**. How that
compares with Hexagonal (Ports and Adapters), Clean Architecture, package
by feature, and a modular monolith, and when adspower should move
towards them, is in [ARCHITECTURE_STYLES.md](../../../docs/ARCHITECTURE_STYLES.md).
Its payoff is that each kind of change touches one place:

| Change | Where |
| --- | --- |
| AdsPower changes an endpoint or JSON field | `api.py` / `models.py` |
| New rule ("proxies must carry the tag") | `client.py` |
| Different matching (e.g. fuzzy names) | `matching.py` |
| New subcommand | `cli/app.py` (parser) + `cli/commands.py` |
| Different table layout, CSV output | `cli/output.py` |
| A GUI instead of a CLI | a new package next to `cli/`; nothing else changes |

## 3. One command, end to end

Following one real command through the layers is the fastest way to
understand the design:

```powershell
adspower set-proxy 1234 -g Jericho --proxy auto
```

1. **`venv\Scripts\adspower.exe`** (generated by pip from
   `[project.scripts]`) calls `mrfactory.adspower.cli.main()`.
2. **`cli/app.py` `main()`** builds the argparse parser and parses the
   arguments into `args` (`args.profile == "1234"`, `args.proxy == "auto"`,
   `args.run == cmd_set_proxy`). It creates `AdsPower(LocalApi(...))`
   and calls `args.run(ads, args)` inside a `try` (the safe-exit
   boundary, §9).
3. **`cli/commands.py` `cmd_set_proxy()`**:
   1. `resolve_profile()` → `ads.find_profile("1234", group="Jericho")`.
   2. **`client.py`** sees `1234` is all digits, so it asks AdsPower for
      exactly that serial number: **`api.py`** POSTs
      `{"profile_no": ["1234"], "page": 1, "limit": 1}` to
      `/api/v2/browser-profile/list`, waiting first if the last request
      was under 0.5 s ago (rate limit), and unwraps
      `{"code": 0, "data": {...}}`.
   3. **`models.py`** turns the JSON row into a `Profile` (typed fields,
      tags as a tuple, the proxy as `socks5://host:port`, password ignored).
   4. The profile has exactly one tag (`jericho`), so that's the proxy tag.
      `ads.choose_proxy(tag="jericho")` lists proxies, keeps those tagged
      `jericho` (**`matching.py`**: case-insensitive), and picks the first unused one.
   5. It prints the plan (`no proxy -> socks5://... (proxy ID 4321)`), then,
      because `--yes` wasn't given, **`cli/prompts.py`** checks whether a person
      is at a terminal: yes → ask "Change it? [y/N]"; no → refuse.
   6. `ads.set_proxy(profile, proxy)` → one POST to `/api/v2/browser-profile/update`.
   7. Prints `Done ...` and returns `0`.
4. `main()` returns `0`; the process exits with code 0.

If anything raised along the way (AdsPower closed, no unused proxy,
Ctrl+C, a bug), step 2's `try` turns it into one clear message and an
exit code. Nothing was changed, because the only change request (3.6)
comes after every lookup and the confirmation.

## 4. The transport: `api.py`

`LocalApi` knows **how** to talk to AdsPower and nothing about what the
data means.

**GET vs POST.** AdsPower's older `/api/v1/` endpoints take query
parameters (`GET /api/v1/browser/start?user_id=...`). The newer
`/api/v2/` ones take a JSON body (`POST` with `{"tag_ids": [...]}`),
which suits lists better. `get()` and `post()` both go through one
`_call()` that sends the request, retries rate limits, and unwraps the
`{"code", "data", "msg"}` **envelope** every response comes in. `code != 0`
becomes an `AdsPowerApiError` with AdsPower's own message.

**Pagination with a higher-order function.** List endpoints return one
page at a time (100 profiles, 200 proxies/tags, 2000 groups per page).
`get_all()` and `post_all()` put the page number in different places, but
share one loop, `_read_all_pages(fetch_page, size)`, by passing in a
*function* that fetches one page:

```python
return _read_all_pages(lambda page: self.post(path, {**body, "page": page, "limit": limit}), limit)
```

The loop stops at the first page shorter than the page size. Passing
behaviour as an argument is what "higher-order function" means. It
removes duplicated loops.

**Rate limiting.** AdsPower allows about 2 requests/second and answers
bursts with `"Too many request per second"`. Two mechanisms:

1. **Throttle** our own requests: at least 0.5 s apart
   (`_wait_for_rate_limit`, using `time.monotonic()`, which never jumps
   when the system clock changes).
2. **Retry** a refusal up to 3 times, 1 s apart. Other programs (or the
   previous command) also count against the limit.

**Retry only what's safe to retry (idempotency).** Reading is
*idempotent*: doing it twice equals doing it once. Creating isn't: if a
create succeeded but its answer was lost, retrying makes a duplicate.
The rate-limit retry is safe even for creates because a refusal means
AdsPower *didn't* do it. That's why only that refusal is retried, never
timeouts or other errors.

**Translate errors at the boundary.** `urllib` raises `URLError`,
`HTTPError`, `ConnectionRefusedError`... `_request()` converts them to
`AdsPowerNotRunning` ("Is AdsPower open?") or `AdsPowerApiError`, with
`raise ... from e` (**exception chaining**) so the original stays
attached for debugging. Nothing above `api.py` knows `urllib` exists.

**Validate input that controls where requests go.** `urllib` opens
more than web addresses: given `file:///C:/...` it would read a local
file. So `LocalApi` accepts only `http://` and `https://` base URLs
(`ALLOWED_SCHEMES`) and raises `ConfigError` for anything else. Ruff's
security rule S310 flags every `urlopen` for this reason; the two
`Request(...)` lines carry a `# noqa: S310` comment that says *why*
it's safe (the scheme was checked in `__init__`).

**Bound every loop that depends on someone else.** Paging stops at the
first short page, but an API that ignored the page number would send
full pages forever. `MAX_PAGES` (1000) turns that into an error. A loop
whose end depends on an outside system should always have a limit.

**Dependency injection.** `LocalApi(opener=...)` receives the function
that actually sends requests (default `urllib.request.urlopen`). Tests
pass `FakeOpener`, so they check real URL/JSON building without a network.

**Standard library only.** No `requests` dependency: GET/POST with JSON
is simple enough for `urllib`, so the package installs anywhere instantly.

**Undocumented endpoints.** The tag endpoints (`/api/v2/browser-tags/list`)
and `profile_tag_ids` aren't in AdsPower's public docs. They came from
AdsPower's own open-source MCP server and were confirmed live. They may
change without notice. Keeping endpoint paths as constants at the top
of `client.py` means a change is a one-line fix.

## 5. The data: `models.py`

**Data Transfer Objects.** The API's JSON is loose: IDs and timestamps
as strings, `"0"` or `""` for "never", `null` remarks, nested tag
objects. `Profile.from_api(row)` and friends convert it **once, at the
boundary**, into typed objects:

```python
profile.last_open_time    # datetime(...) or None, never "0"
profile.tags              # ("jericho",), never [{"id": ..., "name": ...}]
profile.proxy             # "socks5://203.0.113.10:5789", or "" for none
```

Keeping an outside system's quirks at the edge like this is called an
**anti-corruption layer**.

**`@dataclass(frozen=True)`.**

- `@dataclass` writes `__init__`, `__repr__`, and `__eq__` from the
  field list, so tests can compare whole objects.
- `frozen=True` makes instances **immutable**, so nothing can change a
  `Profile` that other code is also holding. (It also makes them safe as
  default argument values; see the `SCREEN_CENTER` note in §11.)
- `from_api` is a `@classmethod` **alternative constructor**, like
  `datetime.fromtimestamp()`: a named way to build the object from a
  specific source, next to the normal constructor.

**Behaviour lives next to its data (encapsulation).**
`Profile.matches(text)`, `Profile.is_exactly(text)`, `Proxy.has_tag(name)`,
`Proxy.in_use`, `Proxy.url`. Callers ask the object instead of digging
into its fields.

**Data minimization.** The API returns proxy usernames and passwords,
in the proxy list *and* inside each profile's proxy settings.
`Proxy` and `Profile` have **no field for them**. Code that never holds a
secret can't print it, log it, or put it in `--json` output by accident.
Tests assert the password appears nowhere.

## 6. The matching rules: `matching.py`

Small **pure functions**: the result depends only on the arguments,
and nothing is read, printed, or changed. `client.py` decides *what to
fetch*. `matching.py` decides *what counts as a match*. Pure functions
are the easiest code to test (`test_matching.py` needs no fakes at all)
and to reuse.

- `contains(text, part)` checks substring ignoring case; `None` means "no filter".
- `find_by_name_or_id(items, wanted)` matches an exact ID, or an exact
  name ignoring case (`jer` doesn't match `Jericho`; that's what
  `contains` is for).
- `serial_order(serial)` is a **sort key**: numbers in number order
  (2 before 10), then text.
- `looks_like_profile_id(text)` decides whether an exact-ID lookup is
  worth a request.

**`casefold()` instead of `lower()`.** It's the Unicode-correct way to
ignore case (`"ß".casefold() == "ss"`).

**`Protocol` and `TypeVar`: typing by shape.** `find_by_name_or_id`
works for `Group` and `Tag` alike, because both have `id` and `name`:

```python
class Named(Protocol):
    id: str
    name: str

N = TypeVar("N", bound=Named)

def find_by_name_or_id(items: Iterable[N], name_or_id: str) -> N | None: ...
```

A `Protocol` describes the *shape* an argument needs, without requiring
inheritance. It's **duck typing that a type checker can verify**. The
`TypeVar` says "you get back the same type you passed in": a list of
`Group`s gives a `Group`.

## 7. The facade and its rules: `client.py`

**Facade.** `AdsPower` is one simple object in front of many endpoints.
Method names read as actions: `groups`, `find_tag`, `profiles`,
`find_profile`, `open_profile`, `choose_proxy`, `set_proxy`,
`create_profile`. Code using them reads like a description:

```python
proxy = ads.choose_proxy(tag="Jericho")
ads.create_profile("Shop 8", group="Jericho", tag="jericho", proxy=proxy)
```

Every `group`/`tag`/`profile` parameter accepts the object *or* a
name/ID string (`str | Group`). Callers use whatever they have. Passing
the object skips a lookup.

**Dependency injection.** `AdsPower(api=...)` receives its transport
(default: a real `LocalApi()`). Tests pass `FakeApi`, so all the rules
below are tested in milliseconds without AdsPower.

**The rules live here, in one place:**

| Rule | Why |
| --- | --- |
| Groups and tags must already exist (`find_group`/`find_tag` raise `NotFound`) | A typo (`Jerico`) must not quietly create a junk tag. *Explicit is better than implicit* (Zen of Python, `import this`) |
| `choose_proxy` only returns proxies carrying the tag; a named ID must carry it too | Proxies stay within their owner's tag |
| `choose_proxy` without an ID picks one **not used** by any profile | Don't share a proxy by accident |
| `create_profile` resolves group and tag *before* the one create request | **Validate first, then change**: a failure leaves nothing half-created |
| `find_profile` rejects blank text | `""` is contained in every name; it would "match" all profiles |

**Exact before fuzzy, and on the server.** `find_profile("1234")`:

1. All digits → ask AdsPower for exactly that serial (one small
   request, `_exact_profile`). An ID-shaped text (`k1abc2de`) → ask for
   that ID.
2. Only if that finds nothing (or it's in another group) → download the
   group's profiles and search names/remarks.

Measured live: **0.4 s** for an exact lookup versus **~3 s** to download
~500 profiles. The general rule: *push filtering to the server when it
supports it; filter on the client only what it can't.* Text search is
the client-side part, because the API has no text filter.

**Who owns the browser decides when it closes.** `open_profile` only
*asks* AdsPower to open the browser (`GET /api/v1/browser/start`).
AdsPower starts it as **its own child process**, so the browser outlives
our program: exit, Ctrl+C, or a crash can't close it. That's exactly
like clicking "Open" by hand. (Tools that *launch* a browser themselves,
like Selenium's `webdriver.Chrome()`, own it, and it usually dies with
the script.) `OpenedBrowser` keeps the `ws://` address so a later tool
can *attach* to it without owning it.

**One change per method.** `set_proxy(profile, proxy)` only sends the
change. *Which* proxy is allowed is decided by whoever called
`choose_proxy`. Keeping "pick" and "apply" separate lets the CLI show
the plan and ask *between* them (§9).

## 8. Errors: `errors.py`

```text
AdsPowerError
├── AdsPowerNotRunning     nobody answered at the API address
├── AdsPowerApiError       it answered, but refused (code != 0, HTTP error, bad JSON)
├── ConfigError            a setting is invalid (e.g. an --api-url that isn't http/https)
├── NotFound               a lookup found nothing
│   ├── GroupNotFound
│   ├── TagNotFound
│   ├── ProfileNotFound
│   └── ProxyNotFound
└── AmbiguousProfile       a lookup found several; .matches holds them
```

- **A hierarchy** lets callers be as specific as they need:
  `except NotFound` covers all four lookups; `except AdsPowerError`
  covers everything this package raises.
- **Errors that carry data.** `AmbiguousProfile.matches` holds the
  candidates. The library doesn't print or ask anything. It *reports*,
  and the caller decides (the CLI shows a picker; a script could take the
  newest).
- **Messages say what to do.** `GroupNotFound` lists the real groups;
  `AdsPowerNotRunning` says "Start it with: adspower open"; a browser
  still downloading says "wait a minute and try again".

## 9. The command line: `cli/`

### Split by job

The CLI used to be one 350-line `cli.py` doing four jobs. Now each job
is its own module (**Single Responsibility**):

| Module | Job | Knows about |
| --- | --- | --- |
| `app.py` | parse arguments, run one command, safe exit | argparse, exit codes, crash log |
| `commands.py` | what each subcommand does | `AdsPower`, prompts, output |
| `prompts.py` | asking the user | `input()`, terminals |
| `output.py` | formatting | tables, JSON |

`output.py` doesn't know about argparse; `prompts.py` doesn't know about
AdsPower. Each can be read, tested, and replaced on its own. That's the
real test of a good split.

### Table-driven dispatch

Each subcommand registers the function that runs it:

```python
sub.set_defaults(run=commands.cmd_set_proxy)
...
return args.run(ads, args)          # main(): no if/elif chain over command names
```

Every `cmd_*` has the same shape, `(ads, args) -> exit code`, and
*raises* errors instead of printing them. Adding a command never touches
`main()`.

### Safe exit: one exception boundary

Every way a command can end goes through `app.main()`:

| What happened | Output | Exit code |
| --- | --- | --- |
| success | the result | `0` |
| known problem (`AdsPowerError`, `FileNotFoundError`) | `error: <what to do>` | `1` |
| Ctrl+C | `Cancelled.` | `130` (128 + signal 2, the shell convention) |
| a bug (any other exception) | one line, plus where details were saved | `1` |

Code below the boundary raises freely and never prints errors. One
place decides how failures look. A bug's traceback isn't thrown at the
user, but it isn't lost either: it's appended to
`%LOCALAPPDATA%\mrfactory\adspower-crash.log` with the time and the
command. `KeyboardInterrupt` is a `BaseException`, not an `Exception`, so it
needs its own `except` (a plain `except Exception` would let Ctrl+C
through as a raw traceback).

**Never write secrets to logs.** The crash log records the command
that failed, and that command may contain `--api-key SECRET`. Logs end
up in bug reports, backups, and screenshots, so `redact()` replaces
secret option values with `***` before anything is written (both
`--api-key X` and `--api-key=X` forms). One subtlety: argparse normally
accepts *abbreviated* options (`--api-k` means `--api-key`), which
`redact()` wouldn't recognize, so every parser is built with
`allow_abbrev=False`. This class of bug has a name: CWE-532,
"Insertion of Sensitive Information into Log File". A security review
found it; `test_unexpected_bug_is_logged_not_dumped` now proves the key
never reaches the file. (Passing the key via `ADSPOWER_API_KEY` is
still better: it stays out of shell history and process lists too.)

### Plan → confirm → apply (for changes)

`set-proxy` changes a real profile, so it follows a fixed pattern:

1. **Plan**: look everything up and validate (profile, tag, proxy).
2. **Show** the plan: `Proxy: no proxy -> socks5://... (proxy ID 4321)`.
3. **Confirm**: `--yes`, or ask `[y/N]` in a terminal. **The default is
   no**, so just pressing Enter changes nothing. With no terminal and no
   `--yes`, refuse: a script must opt in explicitly.
4. **Apply**: exactly one change request.

If the profile already has that proxy, it says "Nothing to change" and
stops. That's *idempotent from the user's side*: running it twice is safe.

### Is anyone there to ask? (`prompts.is_interactive`)

A picker or a `[y/N]` question must only appear when a person can
answer it. Otherwise a scheduled task would wait forever. `sys.stdin.isatty()`
normally tells. **On Windows it's fooled by `< NUL`**, which reports
itself as a terminal. So on Windows, `is_interactive()` also asks the
console for its mode (`GetConsoleMode` via `ctypes`), which only a real
console has. Any closed input (`EOFError`) is treated as "no answer",
never as a crash. (Git Bash's default terminal, mintty, pipes stdin, so
it counts as non-interactive. Use `--yes` there, or run from PowerShell or
Windows Terminal.)

### Make interaction replaceable

`choose()` and `confirm()` take an `ask` function, defaulting to
`input()`. Tests pass scripted answers; a GUI could pass a dialog. Note
the signature is `ask=None` followed by `ask = ask or input`, *not*
`ask=input` (§11).

`commands.py` uses `prompts.is_interactive()` (the module, then the
name) rather than `from .prompts import is_interactive`. So a test that
replaces `prompts.is_interactive` is seen by every caller. With a name
import, each importing module would hold its own copy of the original
function, and you'd have to patch every one.

### Output conventions

- **stdout for results, stderr for errors**, so `adspower groups --json > groups.json` saves only data.
- **Tables for people, `--json` for scripts**, from the same objects.
- **Generated help**: every argument has `help=`, top-level `--help` ends with examples.
- **Shared options via `parents=`**: `--json`, `--api-url`, `--api-key` work after any command.
- **Environment variables as defaults** (`ADSPOWER_API_KEY`), so secrets stay out of shell history.
- **Clean cells**: names with line breaks (one real profile has one) are flattened, long ones shortened.

## 10. Testing strategy

```text
                    live check (throwaway profile, real AdsPower)   ← few, slow, catch reality
           test_cli.py: whole commands with FakeApi, scripted input
     test_client.py: rules with FakeApi   test_api.py: HTTP with FakeOpener
  test_matching.py / test_prompts.py: pure functions, no fakes needed   ← many, instant
```

Each layer is tested **through its own interface with a fake for the
layer below**. A failure points at the layer that's wrong.

| File | Tests | Stand-in |
| --- | --- | --- |
| `test_matching.py` | name/text rules, sort order | none, pure functions |
| `test_prompts.py` | picker, confirm, interactive detection (incl. real `NUL`) | scripted `ask` |
| `test_api.py` | URLs, JSON bodies, headers, envelope, paging, retries, error mapping | `FakeOpener` (replaces `urlopen`) |
| `test_client.py` | every rule in §7, exact lookup request count, proxy changes | `FakeApi` |
| `test_cli.py` | help, tables, JSON, picker, confirm, exit codes, Ctrl+C, crash log | `FakeApi` + patched `input`/`is_interactive` |
| `test_launcher.py` | finding the install, launching | temp folders, mocked `os.startfile` |

**A stateful fake.** `FakeApi` doesn't just return canned data; it
*remembers effects*: which browsers are open, what was created, how
proxies changed. Tests then assert outcomes ("profile #2 now has proxy
p2") instead of only "a request was sent". It deep-copies its data per
instance, so one test's changes can't leak into another.

**Measure, don't guess.** `test_serial_number_is_one_request` asserts the
exact list of requests, which pins the performance fix in place.

**Live checks** use a throwaway profile named `mrfactory test - delete me`
in the Jericho group: create, exercise, then delete in a `finally:` block,
after an `assert` that it's really the test profile. Existing profiles
are never touched.

## 11. Python techniques used

| Technique | Where | What to remember |
| --- | --- | --- |
| Default arguments are evaluated **once** | `prompts.choose(ask=None)` | `def f(ask=input)` captures `input` at definition time; patching it later has no effect. Same root cause as the `def f(items=[])` shared-list bug. Default to `None`, resolve inside |
| Immutable defaults are fine | mouse-ext `tests/fakes.py` `SCREEN_CENTER` | Ruff's B008 warns about calls in defaults; a frozen dataclass can't be mutated, so a named module constant is safe and clearer |
| `KeyboardInterrupt` is a `BaseException` | `cli/app.py` | `except Exception` doesn't catch Ctrl+C |
| `zip(..., strict=True)` | `cli/output.py` | Raises if the lengths differ, instead of silently dropping data (Python 3.10+) |
| `raise X from e` | `api.py`, `client.py` | Keeps the original error as `__cause__` |
| `@dataclass(frozen=True)` + `@classmethod from_api` | `models.py` | Immutable data + named alternative constructor |
| `Protocol` + `TypeVar` | `matching.py` | Type by shape; return the same type you got |
| `next(generator, default)` | `client.current_proxy` | First match or a default, without a loop and flag |
| `map(Class.from_api, rows)` | `client.py` | Apply a constructor to every row |
| `casefold()` | `matching.py`, `models.py` | Unicode-correct case-insensitive comparison |
| `time.monotonic()` | `api.py` | For measuring intervals; immune to clock changes |
| `copy.deepcopy` in fakes | `tests/fakes.py` | Isolate test data between tests |
| Patch where a name is *looked up* | `test_cli.py` patches `cli.app.LocalApi`, `cli.prompts.is_interactive` | `mock.patch` replaces a name in one module's namespace |
| `from __future__ import annotations` | every module | Annotations aren't evaluated at import; allows `X \| None` and forward references cheaply |

## 12. Lessons from testing against the real AdsPower

The fake-based tests check the logic; only the real API shows real
behaviour. Each live run found something the fakes couldn't, and each
finding became a test:

| Found live | Fix | Test |
| --- | --- | --- |
| Back-to-back commands hit "Too many request per second" | throttle + retry the refusal | `test_retries_when_rate_limited` |
| `open-profile ""` matched every profile in the account | reject blank text | `test_blank_text_matches_nothing_instead_of_everything` |
| A new profile can't open while AdsPower downloads its browser | error says "wait and retry" | `test_browser_still_downloading_gets_a_hint` |
| Windows `< NUL` looks like a terminal | console-mode check | `test_windows_nul_is_not_a_console` |
| *Security review:* the crash log saved `--api-key` values in plain text | `redact()` + `allow_abbrev=False` | `test_redact_hides_secret_values_in_both_forms` |
| *Security review:* `--api-url file:///...` would make urllib read a local file | only http/https allowed | `test_only_http_and_https_urls_are_allowed` |
| Looking up one serial downloaded ~500 profiles (~3 s) | exact lookup on the server (0.4 s) | `test_serial_number_is_one_request` |
| Profile tag `jericho` vs proxy tag `Jericho` | all name matching ignores case | `test_filters_by_tag_ignoring_case_and_by_unused` |

The general lesson: **a fake only behaves the way you thought to make
it behave.** Check the real system early, safely (throwaway data), and
turn every surprise into a test.

## 13. Recipe: adding a feature

`set-proxy` was added exactly this way; use it as the worked example.

1. **Find the endpoint** in the [Local API docs](https://localapi-doc-en.adspower.com/)
   (or AdsPower's MCP server source, for undocumented ones). Probe it
   **read-only** first and look at the real JSON.
2. **Data**: new fields → `models.py` (`Profile.proxy`, `Proxy.used_by`).
   Keep secrets out.
3. **Rule/action**: a readable method on `AdsPower` (`set_proxy`,
   `current_proxy`), with the endpoint as a constant at the top of `client.py`.
4. **Command**: parser in `cli/app.py`, `cmd_*` in `cli/commands.py`, an
   example in `EXAMPLES`. If it changes things: plan → confirm → apply.
5. **Tests** per layer: `FakeApi` behaviour (+ make the fake stateful if
   the feature changes things), `run(...)` for the command.
6. **Live check** on a throwaway resource, cleaned up in `finally`.
7. **Docs**: README command table, concepts here, CHANGELOG entry.
8. `ruff check .` and `python scripts/test_all.py`, then commit.

## 14. Known limits

- **Proxy tags can't be set via the API.** Tag proxies in the AdsPower
  app (Proxies → Proxy List).
- **Tag endpoints are undocumented** (§4) and may change.
- **Profile text search downloads the profiles** (filtered by group/tag
  first) because the API has no text filter.
- **A changed proxy applies when the browser next opens.** If it's
  open, the CLI tells you to close and reopen it.
- **The picker and `[y/N]` need a real console**: PowerShell or Windows
  Terminal, not Git Bash's mintty. Use `--yes` / exact serial numbers in scripts.
